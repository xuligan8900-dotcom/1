# Подключение поддержки за Robux

Начиная с версии5.0 монеты, косметика и обработка квитанций реализованы. **Продукты ещё не созданы, их ID равны0, реальные продажи отключены.** Для работы магазина за заработанные монеты это не мешает. Создание продуктов требует владельца experience в Creator Dashboard; код не создаёт их через чужие credentials.

## 1. Опубликуйте experience

Откройте новый `build/MechanicalTower-v6.0.rbxlx` в Roblox Studio и опубликуйте его в нужный experience. Сначала используйте отдельный тестовый experience для проверки сохранения и платёжной логики. В публичной игре используется реальный DataStore; StudioPersistence=false касается только Studio.

## 2. Создайте три Developer Products

В [Creator Dashboard](https://create.roblox.com/dashboard/creations) выберите нужный experience → **Monetization → Developer Products → Create** (названия меню могут меняться в интерфейсе Roblox).

| Ключ в коде | Продукт | Выдача |
| --- | --- | --- |
| coins_small | 250 монет | 250 монет + титул поддержки |
| coins_medium | 1000 монет | 1000 монет + титул поддержки |
| coins_large | 3000 монет | 3000 монет + титул поддержки |

Укажите название, описание и желаемую цену в Robux. Например, описание должно прямо говорить, что монеты расходуются на косметику и PvP-дубинки; дубинки отбрасывают других игроков, но не увеличивают скорость/прыжок владельца. Это повторяемые наборы, поэтому используются Developer Products, а не одноразовые game passes. Цена подтверждается официальным окном Roblox; код не угадывает её и не проводит внешние платежи.

## 3. Вставьте ID

Скопируйте **Product ID** каждого продукта. Это не ID experience, place, ассета или game pass. В Studio откройте:

`ServerScriptService → TowerServer → CommerceConfig`

Либо измените исходник `src/server/CommerceConfig.luau` и синхронизируйте Rojo. Замените три нулевых ProductId на соответствующие реальные числовые ID. Другие суммы не меняйте без изменения описания продукта.

ID продуктов не являются секретными. Не нужны пароли Roblox, .ROBLOSECURITY, API-ключи или вставка токенов в код. После изменения снова опубликуйте place; уже запущенный старый сервер может оставаться на предыдущей версии до перезапуска/нового подключения.

После запуска в опубликованной игре сервер запрашивает метаданные продукта через GetProductInfoAsync. При корректном ID и доступной продаже кнопка перестаёт показывать «Скоро». В Studio кнопки покупки за Robux намеренно отключены; earned-coins магазин работает для проверки интерфейса.

## 4. Проверьте транзакцию

Официальное окно Roblox показывает точную стоимость перед подтверждением. Отмена не выдаёт монеты или титул. После подтверждения сервер должен получить ProcessReceipt, атомарно записать баланс и PurchaseId, затем показать сообщение о покупке. Перезайдите и проверьте баланс/инвентарь. Повторная квитанция не должна начислять сумму повторно.

В облаке проверены чистые правила и реальный адаптер ReceiptProcessor с имитацией успешной записи, потерянного ответа, повторов и ошибок. **Roblox checkout, реальное списание Robux и live DataStore здесь не выполнялись.** Не считайте опубликованный магазин проверенным по одному открытию purchase prompt; нужна проверенная квитанция и сохранённая выдача.

## Две постоянные донатные дубинки v6.0

Для оружия используются **Game Passes**, а не повторяемые Developer Products. Покупка даёт постоянное владение одной дубинкой; повторной покупки того же пропуска Roblox не требует.

1. В Creator Dashboard нужного experience откройте **Monetization → Passes** и создайте два пропуска: «Плазменная дубинка» и «Космическая дубинка». Укажите цену/настройку продажи. В описании честно укажите отбрасывание и параметры, это игровые PvP-предметы.
2. Скопируйте **Game Pass ID**, не ID картинки. В том же `ServerScriptService/TowerServer/CommerceConfig` заполните `GamePasses[1].PassId` и `GamePasses[2].PassId` вместо0. Ключи club_plasma/club_cosmic и ItemId не меняйте.
3. Опубликуйте новый place. Эти записи не заменяют ProductId трёх наборов монет: в конфигурации3 Developer Products и2 Game Pass, у каждого свой ID.
4. В опубликованной игре откройте вкладку «Дубинки» или «Донат». Roblox показывает официальное окно Game Pass-покупки. После покупки сервер проверяет UserOwnsGamePassAsync; при подтверждённом владении предмет появляется в коллекции, и его можно надеть. Титул поддержки выдаётся дополнительно.
5. При следующем входе уже принадлежащий пропуск проверяется повторно, если предмет ещё не записан. Если Marketplace/DataStore временно недоступны, сохранённое владение не удаляется, а новая выдача может задержаться до следующей проверки. Открытие магазина позволяет повторить проверку с ограничением частоты.

Пока PassId=0, кнопка «Скоро» не проводит оплату. В Studio платежи через магазин отключены. Ни реальная покупка пропуска, ни live-проверка Roblox API в облаке не выполнялись; PassProcessor протестирован на имитации подтверждённого владения, отказа и ошибки записи. Физику отбрасывания нужно проверять минимум двумя клиентами в Studio.

## Обработка ошибок и сопровождение

- Выдача зависит от ProcessReceipt, а не сообщения клиента или PromptProductPurchaseFinished.
- Неизвестный ProductId, отсутствие игрока/кошелька или неуспешная запись дают NotProcessedYet. Roblox может повторить доставку; самодельных возвратов Robux или ложного PurchaseGranted в коде нет.
- Не удаляйте старые продукты из обработчика и не меняйте их выдачу задним числом: могут прийти старые незавершённые квитанции. Для нового предложения создайте новый продукт и сохраните обработку старого ID.
- Не добавляйте второй независимый ProcessReceipt из стороннего скрипта: в игре должен быть один согласованный обработчик всех Developer Products.
- Ключи `MechanicalTower_Economy_v1/u_<UserId>` содержат историю PurchaseId. Суточный сброс очищает только Collected, а не квитанции, кошелёк или инвентарь. Удаление истории может привести к повторной выдаче старой покупки.
- Если цена/продукт недоступны, кнопка остаётся выключенной. Проверьте ID, принадлежность продукта нужному experience, настройку продажи и сообщения `[Commerce]` в Output. Не заменяйте ID случайными значениями.

Документация Roblox: [Developer Products](https://create.roblox.com/docs/production/monetization/developer-products), [MarketplaceService](https://create.roblox.com/docs/reference/engine/classes/MarketplaceService).
